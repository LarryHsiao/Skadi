Rúmil — the flow

A product spec goes in; an engineering plan comes out, and the questions go back. The sift is the only loop.

The road

The rules — a text spec an Outline wiki page, a markdown file, or prose. States what must be true; never draws the flow.
The screens — a UI spec a Figma file (preferred) or exported frames. Draws the flow; never states the rules.
▼   ▼
STEP 1
Read both specs
What arrives already reads plan-shaped — that is the trap. A Figma file is structured data, so frame names, same-row order and design tokens are read directly rather than squinted out of a screenshot. A ticket key is only a place to find links, never a spec.
▼
STEP 1b
Wire the two specs to each other
The step nobody else performs. Bind every screen to the rule that governs it, and every rule to the screen that exercises it. The correspondence is written down nowhere — today it is assembled in the head of whichever engineer reads both documents, and it evaporates when they move on.

Three findings fall out, each a numbered question, never a quiet reconciliation: orphan screen (drawn, ungoverned) · orphan rule (stated, undrawn) · contradiction (the text says one thing, the mock another — never pick a winner).
▼
STEP 2
Read the ground — bind every product noun
“the receipt list”, “the sync banner” → a real file:line, or else a new surface earning its own steps. A noun that binds to neither is a misunderstanding, and becomes a question.
▼
STEP 3 · 3b · 3c
Distil, walk the undrawn states, write the questions
Purpose, then acceptance that something can actually fail. Every screen walked against the seven undrawn states. What remains unanswered is numbered Q1…Qn — in the author's language, never filled by guesswork.
▼

STEP 4 The sift — the loop

Number every step 1..N. Render the verdict table in chat — a silent sift is not a sift. Then gauge each step against four signals; all four must hold for minimum.
ONE SEAMone file, or one file and its test
ONE CHECKa single named verification proves it
ONE REVERTone git revert, tree still builds
NO CONJUNCTIONno “and”, no “then”, no second verb
↻ any step fails Split it into 2–4 children, renumber, and gauge again from the top — a split shifts every later number and can invert a dependency.
✓ a pass splits nothing Converged. A first pass that splits nothing is suspicious, not successful — name which signal each step passes.
The ceiling — four passes. A step still failing is marked [WILL NOT CLEAVE] and reported with its failing signal. Never relabelled minimum to force the loop shut: a false minimum is worse than an honest medium, because the next session trusts it.
▼
STEP 5 · 6
Order, tag, and sketch
Phases group the steps; numbers stay global so a dependency reads unambiguously. [independent] [depends on N] [blocked on Qn]
A spec that changes screens also gets flow-<slug>.html beside the concept, each arrow carrying the rule that governs it — or marked unwired with its question number.
▼
STEP 7 · 8
Write the concept, mirror it
docs/plans/<slug>.md — the source of truth — plus a Henneth mirror for the eye.

What Rúmil refuses to carry across

  • ✕Its milestones are not your steps. “M2 — sync” is a fortnight of work. It may become a phase heading; it is never a step.
  • ✕Its acceptance is not your acceptance. “Feels instant”, “delightful”, “works reliably” are product intent, not checks.
  • ✕What is not drawn is not decided. A screen sketched in one state has had one state designed — not all of them.
  • ✕A contradiction is not yours to settle. Both sides are quoted and the question goes back.
Never sharpen product language into a criterion of your own invention. A fabricated threshold reads as the author's decision once written down, and nobody will remember it was yours.

The seven undrawn states

State The question it asks
Empty first run — what stands where content would be?
Loading spinner, skeleton, or nothing?
Error what is shown, and what can they do next?
Offline work, degrade, or block?
Permission camera or location declined — then what?
Overflow longest name, hundredth row — layout holds?
Interruption back mid-flow, app killed — what survives?

Walked against every screen. Never answered by Rúmil — a default invented here becomes an unowned decision the author never made.

The translation, line by line

The spec says Verdict Becomes
“the queue drains in capture order once the network returns” keeps An acceptance line as written — something can already fail it.
“syncing feels instant” question Q3: what is the budget, and measured from which moment?
“handles errors gracefully” question Q4: which errors, and what does the user see?
“M2 — sync” phase A ### Phase 2 heading. The steps beneath it are Rúmil's to derive.
The test for a question: could the person who wrote the spec answer it without opening the codebase?
good Q3: When a receipt is rejected, does the app retry on its own, or wait for the courier to resubmit it?
bad Q3: Retry semantics for the 422 branch of ReceiptDrain.next?
