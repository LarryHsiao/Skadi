---
name: .gitignore sane
scope: project
---

A foundation project has a `.gitignore` that excludes the obvious build, dependency, IDE, and secret noise. Without one, generated files and personal settings leak into the repo and bloat the diff for everyone.

Scan the project root for `.gitignore`. The file should cover the noise generated by the project's primary stack. Common patterns by language:

- Flutter / Dart: `.dart_tool/`, `build/`, `.flutter-plugins`, `.flutter-plugins-dependencies`, `.fvm/` (when applicable).
- TypeScript / JavaScript: `node_modules/`, `dist/`, `build/`, `.next/`, `.nuxt/`, `coverage/`, `.parcel-cache/`.
- Go: built binaries, `vendor/` (when the project does not commit it).
- Rust: `target/`, `Cargo.lock` for libraries (kept for binaries).
- Python: `__pycache__/`, `*.pyc`, `.venv/`, `venv/`, `.pytest_cache/`, `dist/`, `*.egg-info/`.
- Swift / iOS / macOS: `*.xcuserstate`, `xcuserdata/`, `Pods/` (when not committed), `DerivedData/`.
- Kotlin / Android: `build/`, `.gradle/`, `local.properties`.
- Common to all: `.env`, `.env.local`, `.DS_Store`, `Thumbs.db`, `.idea/`, `.vscode/` (when not opted in for the team).

Pass when:
- `.gitignore` exists at the project root.
- AND it covers the relevant build output and dependency directories for the project's primary language.

Fail when:
- No `.gitignore` is found.
- `.gitignore` exists but is empty or covers only one or two trivial entries (e.g. only `.DS_Store`).
- The repository currently tracks files that should be ignored (e.g. `node_modules/` committed, `.env` committed, `*.log` committed) — even if `.gitignore` lists them, the existing tracked copies must be removed.

n/a when:
- The repository is documentation- or asset-only with no build pipeline.

On fail, name what is missing from the file or, if applicable, what is currently tracked that should not be.
